# Governance

skill-ci is a maintainer-led project. This document describes how decisions are made today, while the project has a single maintainer. It will change as the project grows.

## Maintainers

The maintainers are listed in [MAINTAINERS.md](MAINTAINERS.md). They:

- review and merge pull requests,
- triage issues and security reports,
- cut releases,
- decide the direction of the project and keep the [roadmap](ROADMAP.md) current,
- uphold the [Code of Conduct](CODE_OF_CONDUCT.md).

## Decision making

Decisions are made in the open, in issues and pull requests, by lazy consensus: a proposal is accepted when no maintainer objects within a reasonable time, at least one week for larger changes. Anyone may comment, and maintainers take every argument into account.

If a maintainer objects and the discussion does not resolve it, the maintainers vote, and a simple majority decides. While there is only one maintainer, that maintainer decides and writes down the reason in the issue or pull request.

Changes to this document, to the license, or to the list of maintainers need the approval of a majority of the maintainers.

## Adding maintainers

A contributor can become a maintainer after a sustained record of contributions, such as reviews, code, documentation or issue triage, and after showing good judgment in reviews. Any maintainer can nominate a contributor, and a contributor can ask to be nominated. The nomination is accepted when a majority of the maintainers agree. The new maintainer is added to MAINTAINERS.md in a pull request.

The project wants maintainers from more than one company.

## Removing maintainers

A maintainer can step down at any time by opening a pull request against MAINTAINERS.md. A maintainer who has been inactive for six months, or who breaks the Code of Conduct, can be removed when a majority of the other maintainers agree. A former maintainer can be nominated again later.

## Changes to this document

This model fits a project with one or two maintainers. When the project has more maintainers, or joins a foundation, the maintainers will update this document in a pull request.
